\begin{abstract}
%% Every sentence here traces to a row of paper/CLAIMS.md. The hardware
%% sentence is deliberately the weakest one in the abstract, because the
%% strongest hardware result available is a failure.
Serving a large language model on a heterogeneous cluster means choosing which
accelerators run which role at which degree of parallelism. Planners that
enumerate configurations over groups of interchangeable devices cannot express
that choice, because two placements of one configuration are, to them, one
candidate---and on real hardware the difference between two such placements is
large enough to move the load at which a service still meets its latency
target.

We enumerate placements instead, and make the resulting space tractable with an
equivalence relation that folds two placements only when a graph isomorphism
confirms their candidate graphs agree. Those graphs carry the shared
communication boundary, so placements alike in every local attribute but
crossing different contended links are kept apart; removing the boundary from
the signature produces mis-merges that the full relation does not. Elimination
is a relaxation of the feasibility test---a candidate is removed only when
arithmetic optimistic on every uncertain term still misses a declared
constraint---and each check publishes the optimism it assumed. The evaluation
budget is bounded and reports what it never reached, because a search that
omits what it did not evaluate has made a claim about a space from evidence
about part of it.

Across every experiment reported here no feasible candidate was wrongly
eliminated and no two differently-priced placements were folded together; both
counts are reported for every arm rather than summarised once. Under a
discrete-event simulator the compression saved more time than it cost, with its
own hashing and isomorphism checks charged against it. On hardware we measure
that a contention model's accuracy depends on which resource a cluster
description claims is shared---a claim we found to be wrong on one bus and
exactly right on another---and that an optimistic throughput bound, while never
eliminating a candidate it should not, sits an order of magnitude above the
capacity the machine delivers.
\end{abstract}
