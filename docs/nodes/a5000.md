## Rules that are easy to forget on a new machine

These live in the A40 node's Claude Code memory, which does not travel:

- Reply to the user in Korean; code, commits and documents in English.
- `--predictor sim` runs touch no GPU; `--max-workers` means CPU cores.
  Never run a simulation while hardware is being measured on the same node.
- GPUs may be used without asking, but record their occupancy (`nvidia-smi`
  before and after) in every raw file, and never measure beside another tenant.
- `pkill -f X` / `kill $(pgrep -f X)` kills the calling shell whenever `X`
  appears anywhere in the same command: issue kills as their own command.
- heteropilot's `compile.sh` aborts on its own bare `pip3`, and heteropilot's
  `.gitignore` does not cover `.venv`: see `REPRODUCE.md` (the
  `info/exclude` lines) and `docs/nodes/PREP.md` step B.

## R4.2 — the profile (run on this node, in heteropilot, not here)

The profile is heteropilot data, so it is a heteropilot PR followed by a
submodule bump here. **Never edit `vendor/heteropilot`**: profile in a
separate heteropilot clone.

The existing A5000 bundle (`profiler/perf/A5000/meta-llama/Llama-3.1-8B/bf16`)
was made with vLLM 0.19.0, `tp_degrees: [1]`, `max_num_batched_tokens 2048`,
`max_num_seqs 256`, `attention_max_kv 16384`, factors 2.0, 3 measurement
iterations. Match every one of those; change only the TP list. The profiler
resumes by default -- an existing CSV keeps its rows -- so **do not pass
`FORCE`**: tp=1 must stay byte-identical (the E-G6 mock and every earlier
result read it), and the checksums below prove it did.

Record, in the table at the end of this file, before the run: node name,
GPU model and count, every GPU's UUID (`nvidia-smi -L`), driver
(`nvidia-smi --query-gpu=driver_version --format=csv`), CUDA, the process
binding used, `uptime` load, and `nvidia-smi` occupancy (must be empty).

### The links, measured

`ib_write_bw --report_gbits -F -D 5`, RDMA write, 64 KiB messages, 2026-10-08,
no GPU process on either end:

| --- | --- |
| `a5000-2` -> `s8` | 53.63 |

All three hit the same ceiling as the direct RoCE link did (53.71 Gb/s): the
A5000 NICs' PCIe Gen3 x8 slots, not the fabric. These are verbs figures for
orientation. They are **not** PREP.md step D's `LinkMeasurement`, which is the
NCCL busbw under `torchrun` that heteropilot's link records hold.

For R5, point NCCL and NIXL at the fabric explicitly:

- on the A5000 nodes: `NCCL_IB_HCA=mlx5_1`, `UCX_NET_DEVICES=mlx5_1:1`, and
  `NCCL_SOCKET_IFNAME=eno1`;
- on the A40 node: `mlx5_0`, and `enp35s0f0np0`.

GPUDirect RDMA needs `nvidia_peermem` at both ends, and `a5000-2` does not have
it: it runs inbox drivers on kernel 6.8. A P/D transfer that lands on
`a5000-2`'s GPUs therefore goes through host memory unless MLNX_OFED (or a
`nvidia_peermem` build for 6.8) is installed there. Check this before R5
attributes a transfer time to the link.

## R4.2 as run

- **The profiler emulates TP on one GPU.** `profiler/core/engine.py` keeps the
  engine at `tensor_parallel_size=1` and divides `intermediate_size`,
  `num_attention_heads` and `num_key_value_heads` by tp, so a tp=N profile is
  the per-rank kernel shapes on GPU 0 and nothing else; GPU 1 stayed idle. The
  "fewer than four GPUs" caveat in the commands above therefore does not
  apply: **tp=4 was profiled here too**, as a second run after tp=2 (resume
  skips the degrees already on disk). Communication is not in these files at
  all; the simulator models it separately.
- tp=1 was resumed, not re-run: every category reported "nothing to do"
  (dense 152 shot keys, per_sequence 40, attention 8643, skew 13009 cases).
- Both runs ended `EXIT=0` with no other process on either GPU before or
  after. Wall time per degree: attention 52 min, skew about 5 h 20 min
  (tp=2 03:59-10:12 UTC, tp=4 10:13-16:28 UTC, 2026-10-06).
- **tp=1 is byte-identical**: the md5 of all five `tp1/` files matched before
  the first run and after the second.
- Skew-fit relative error p50 / p90 / p99: tp=2 0.78 / 3.87 / 10.88 %, tp=4
  0.83 / 4.44 / 12.76 % (tp=1: 0.83 / 4.17 / 9.6 %).
- The profiler's rewrite of `meta.yaml` dropped `tier: measured`, which would
  have made the bundle resolve to `UNKNOWN`; restored by hand (heteropilot
  D129).
- `profiles/accelerators/a5000.yaml` keeps `max_tp_size: 1` although its
  comment's condition ("raise this once tp2/ exists") is now met: raising it
  changes heteropilot's default-path candidate space, so it is a separate PR
  and deviation when needed (user decision, recorded in D129).
- Raw logs, `nvidia-smi` before and after each run, and the tp=1 checksums:
  `~/a5000-r42-raw/` on this node.
- **What cannot be shown:** that the 2026-08-07 tp=1 bundle was measured on
